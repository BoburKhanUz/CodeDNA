# Internal Analyzer Contract — v1

- **Contract version:** `1.0`, **frozen in Phase 08** with the amendments
  listed in [§ 9](#9-amendments) (Phase 08, and the additive Phase 09
  `static_analysis` result type, which a request opts into; the Phase 08
  `foundation` result stays the default, unchanged). Implemented by the analyzer (`analyzer/app`);
  the Laravel client arrives in Phase 10.
- **Audience:** Laravel backend (client) and the Python analyzer (server)
- **Decision record:** [ADR-005](../decisions/ADR-005-service-communication.md)

> This API is **internal only**. It is never routed through the public Nginx,
> never exposed to browsers, and never documented as part of the public
> `/api/v1`.

## 1. Transport

| Property | Value |
|---|---|
| Base URL | `ANALYZER_URL` (e.g. `http://analyzer:8000` on the private network) |
| Protocol | HTTP/1.1, JSON (`application/json; charset=utf-8`) |
| Versioning | Major in the path (`/internal/v1/...`); `contract_version` (`MAJOR.MINOR`) in bodies |
| Compatibility | Within `v1`, the server ignores unknown request fields, and clients ignore unknown response fields. Removing or redefining a field requires `v2`. |

Machine-readable JSON Schemas for these payloads are published in
[`packages/api-contracts/analyzer/v1/`](../../packages/api-contracts/README.md):
the request, the foundation result (including the IR 1.0 file record) and the
error envelope. The analyzer validates real requests and responses against
them in its tests; the Laravel client will do the same in Phase 10.

## 2. Endpoints

| Method | Path | Auth | Purpose |
|---|---|---|---|
| `POST` | `/internal/v1/analyze` | HMAC | Analyze one source snapshot (synchronous) |
| `GET` | `/internal/v1/health` | none | Liveness/readiness for container health checks. Returns only `status`, `versions` and non-sensitive `limits`. |

```json
{
  "status": "ok",
  "versions": { "analyzer": "0.2.0", "contract": "1.0", "ir": "1.0" },
  "limits": {
    "hard_timeout_seconds": 240, "max_archive_bytes": 52428800, "max_extracted_bytes": 209715200,
    "max_files": 20000, "max_entry_bytes": 26214400, "max_file_bytes": 1048576,
    "max_path_length": 512, "max_concurrency": 2,
    "parse_timeout_ms": 5000, "max_ast_nodes": 1000000, "max_total_ast_nodes": 10000000, "max_parsed_files": 20000
  }
}
```

The analyzer is reachable only on the `codedna-internal` Docker network: it
publishes no host port, Nginx returns `404` for `/internal/*`, and neither
Nginx nor the frontend can reach it. Every response carries `X-Request-ID`
(the caller's UUID, or a new one).

## 3. Request authentication (HMAC)

### Headers (all required on `POST /internal/v1/analyze`)

| Header | Description |
|---|---|
| `X-Request-ID` | UUID (36 characters) generated by Laravel for this attempt. It is logged by both services and stored on the run. A new one per attempt: an ID is accepted only once (replay protection). |
| `Idempotency-Key` | The `analysis_run_id` (ULID). It is the same for every attempt of the same run. |
| `X-CodeDNA-Timestamp` | Unix time in seconds (integer) when the request was signed |
| `X-CodeDNA-Signature` | `v1=<lowercase hex HMAC-SHA256>` |

### Canonical string

```text
v1\n
<X-CodeDNA-Timestamp>\n
<HTTP method, uppercase>\n
<request path, without scheme/host, including query string if any>\n
<X-Request-ID>\n
<lowercase hex SHA-256 of the exact raw request body bytes>
```

Lines are joined with a single `\n`, and there is no trailing newline. The key
is `ANALYZER_HMAC_SECRET`, used as raw UTF-8 bytes. It must be at least 32
random bytes, encoded as hex or base64.

### Verification rules (analyzer)

1. Reject with `401 INVALID_SIGNATURE` if any header is missing or malformed
   (timestamp: 1–12 digits; signature: `v1=` + 64 lowercase hex;
   request ID: a UUID).
2. Reject with `401 STALE_TIMESTAMP` if `|now − timestamp| > 300` seconds
   (past or future).
3. Compute the signature with the current secret, and also with
   `ANALYZER_HMAC_SECRET_PREVIOUS` if that is set (used during rotation).
   Compare in **constant time** (`hmac.compare_digest`). Reject with
   `401 INVALID_SIGNATURE` if neither matches.
4. Reject with `401 REPLAY_DETECTED` if this `X-Request-ID` was already
   accepted within the window (§ 9). This and every later response is signed.
5. The body is parsed only **after** verification succeeds.

Because the exact transmitted body bytes are hashed, neither side needs to
canonicalize JSON for signing: any change to the bytes (key order,
whitespace, escaping) is simply a different, unsigned body. The path is the
raw request path as sent, including `?query` if present. Request bodies
are at most 64 KiB.

### Response signing

Every response to an authenticated request, including errors after
successful verification, carries `X-CodeDNA-Timestamp` and
`X-CodeDNA-Signature`. They are computed over:

```text
v1\n<timestamp>\n<HTTP status code>\n<request path>\n<X-Request-ID>\n<hex SHA-256 of raw response body>
```

Laravel verifies the response signature before trusting a result. A response
that fails verification is treated as a transport failure, which is
retryable.

## 4. `POST /internal/v1/analyze`

### Request body

```json
{
  "contract_version": "1.0",
  "analysis_run_id": "01JBX7T3K4Q9Z8V6M2N5P1R0SA",
  "attempt": 1,
  "source": {
    "type": "archive",
    "format": "zip",
    "url": "https://<storage-host>/<object-key>?<presigned-query>",
    "sha256": "<64 lowercase hex chars>",
    "size_bytes": 1048576
  },
  "options": {
    "languages": ["php", "python", "javascript", "typescript"]
  }
}
```

| Field | Rules |
|---|---|
| `contract_version` | Must have major `1`. Otherwise `400 UNSUPPORTED_CONTRACT_VERSION`. |
| `analysis_run_id` | ULID. Must equal `Idempotency-Key`. |
| `attempt` | Integer ≥ 1. Informational (logging). |
| `source.type` / `source.format` | Only `archive` / `zip` in v1.0 |
| `source.url` | SigV4 pre-signed GET URL (ADR-003) for an object key ending in `projects/<ULID>/snapshots/<ULID>/source.zip`. Its host must be exactly one of `ANALYZER_ALLOWED_SOURCE_HOSTS`, and it must be HTTPS except for hosts in `ANALYZER_LOCAL_SOURCE_HOSTS` (local development). Every address the host resolves to must be public (local hosts: private, but never loopback, link-local/metadata, multicast, unspecified or reserved); the analyzer connects to the validated address. Expired URLs → `422 SOURCE_URL_EXPIRED` (retryable with a fresh URL); lifetime ≤ `ANALYZER_MAX_URL_LIFETIME_SECONDS`. Redirects are **not** followed. Any other violation → `422 SOURCE_HOST_NOT_ALLOWED`. |
| `source.sha256`, `source.size_bytes` | Verified after download. A mismatch → `422 SOURCE_CHECKSUM_MISMATCH`. |
| `options.languages` | Optional non-empty subset, without duplicates, of `c`, `cpp`, `csharp`, `go`, `java`, `javascript`, `php`, `python`, `rust`, `typescript`. Omitted means all of them. |
| `options.result_type` | Optional: `"foundation"` (default) or `"static_analysis"` (Phase 09). Selects which result type the run produces; any other value → `422 INVALID_REQUEST`. It is part of the run's identity: reusing an `analysis_run_id` with a different `result_type` → `409 RUN_CONFLICT`. An analyzer older than Phase 09 ignores the option and returns `foundation`, so a client always checks `result_type` in the response. |

### Result types

```text
FOUNDATION         (Phase 08, default)   source intake + file inventory, IR 1.0
   │  every field kept, with the same meaning
   ▼
STATIC ANALYSIS    (Phase 09, opt-in)    + parsing, IR 1.1, static metrics, structural findings
   │  every field kept
   ▼
future DNA / competency analysis (Phase 11+: "full", adds features and scores)
```

Each layer is a superset of the one before: it adds fields and never
removes, renames or redefines a field of the layer below. The only values
that differ are those that name what the result contains: `result_type`,
`versions.ir` (`1.0` → `1.1`), `versions.metrics` (`null` → `1.0`), the
`versions.parsers` map, and therefore `result_hash`. Each result type has its
own JSON Schema and its own deterministic `result_hash`.

Parsing is strict: duplicate JSON keys and type coercion (e.g. `"1"` for an
integer) are rejected as `422 INVALID_REQUEST`, whose `details.fields` names
the offending fields (never their values). An `Idempotency-Key` that differs
from `analysis_run_id` is also `INVALID_REQUEST`.

`versions.scoring` is `null`; Laravel must not create a DNA snapshot from it.

Definitions: [analyzer.md](../architecture/analyzer.md#parsing-phase-09)

- Every foundation field keeps its name and meaning (`source`, `languages`,
  the IR 1.0 fields of every file record and the Phase 08 `analysis` keys are
  identical to the foundation result of the same source). Added:
  `versions.parser_runtime`, the parser limits in `analysis`, `parsing`,
  `parse`/`structure` per file record (IR 1.1), `metrics`, `findings`.
- Each analyzable file has exactly one `parse.status`: `PARSED`,
  `PARSE_ERROR`, `PARSE_TIMEOUT`, `LIMIT_EXCEEDED` (with `limit`) or
  `UNSUPPORTED_PARSER`. Only `PARSED` files have `structure` and contribute
  to `metrics`. One failing file never fails the run.
- A metric that cannot be computed is `null`, never `0`; metrics a language
  cannot provide are also listed in that group's `unsupported`.
- Findings carry `rule_id`, `severity`, `path`, `line`, `column`, `value`,
  `threshold` and a fixed-format `message`. They never contain names,
  snippets or source text. At most 2,000 items; `total`, `by_rule` and
  `truncated` describe the full set.
- `result_hash` is computed as for the foundation result. It is identical
  for identical source bytes, versions and configuration, except when a file
  is `PARSE_TIMEOUT` (wall-clock dependent; reported in `parsing.files`).

## 5. Errors

Error codes use the same `UPPER_SNAKE_CASE` vocabulary style as the public
API ([docs/api/README.md](README.md#error-codes)). The internal envelope
adds `retryable`. All error responses use this shape:

```json
{
  "error": {
    "code": "SOURCE_TOO_LARGE",
    "message": "Archive exceeds the maximum allowed size.",
    "retryable": false,
    "request_id": "6f1c2a4e-1d3b-4c55-9a7e-2b8f0c9d1e23",
    "details": { "limit_bytes": 52428800 }
  }
}
```

`message` is safe to show to the user. It never contains source code,
secrets, file contents, internal hostnames or stack traces.

| HTTP | `code` | `retryable` | Meaning |
|---|---|---|---|
| 400 | `UNSUPPORTED_CONTRACT_VERSION` | false | Unknown contract major |
| 401 | `INVALID_SIGNATURE` | false | Missing or bad HMAC headers or signature |
| 401 | `STALE_TIMESTAMP` | false | Timestamp outside ±300 s |
| 401 | `REPLAY_DETECTED` | false | This `X-Request-ID` was already accepted within the window |
| 404 | `NOT_FOUND` | false | Unknown path |
| 405 | `METHOD_NOT_ALLOWED` | false | Wrong method for the path |
| 409 | `RUN_IN_PROGRESS` | true | The same `Idempotency-Key` is already being processed |
| 409 | `RUN_CONFLICT` | false | The same run was requested with a different source or options (in flight or recently completed) |
| 413 | `SOURCE_TOO_LARGE` | false | Archive, single entry (`details.reason: entry_too_large`) or extracted size (`extracted_too_large`) limit exceeded |
| 413 | `TOO_MANY_FILES` | false | File count limit exceeded |
| 422 | `INVALID_REQUEST` | false | Body fails schema validation, is too large, or the `Idempotency-Key` does not match |
| 422 | `SOURCE_HOST_NOT_ALLOWED` | false | The URL violates the source policy (host, scheme, address, key layout, not pre-signed) |
| 422 | `SOURCE_URL_EXPIRED` | true | The pre-signed URL has expired; retry with a fresh URL |
| 422 | `SOURCE_CHECKSUM_MISMATCH` | false | Size or SHA-256 differs from the request |
| 422 | `INVALID_ARCHIVE` | false | Corrupt or unsafe archive; `details.reason` is a fixed identifier such as `path_traversal`, `absolute_path`, `drive_path`, `backslash`, `symlink`, `special_file`, `encrypted`, `overlapping_entries`, `corrupt` |
| 422 | `NO_SUPPORTED_FILES` | false | Nothing analyzable after filtering |
| 502 | `SOURCE_FETCH_FAILED` | true | Storage returned an error or a redirect, the connection failed or timed out (`details.reason`) |
| 503 | `ANALYZER_BUSY` | true | Concurrency limit reached; includes a `Retry-After` header |
| 504 | `ANALYSIS_TIMEOUT` | false | Hard time limit exceeded. Deterministic input means a retry would time out again. |
| 500 | `INTERNAL_ERROR` | true | Unexpected failure (bug); details are only in the analyzer logs |

Transport failures, such as a connection refused, a Laravel-side timeout or
a response signature that fails verification, are treated by Laravel as
retryable with the code `ANALYZER_UNREACHABLE`.

`details` only ever holds fixed identifiers and numbers (`reason`,
`fields`, `limit_bytes`, `limit_files`, `status`), never submitted values,
paths, URLs or exception text. Errors before successful authentication are
unsigned; every later error is signed like a success.

## 6. Idempotency

- The analyzer keeps an in-memory map of in-flight `Idempotency-Key`s with
  each run's fingerprint (run ID, contract major, source type, format,
  SHA-256 and size, and the analysis configuration; not the URL). A
  concurrent duplicate gets `409 RUN_IN_PROGRESS`; a concurrent request for
  the same run with a different fingerprint gets `409 RUN_CONFLICT`.
- Completed results are kept in a small cache bounded by size and age
  (32 MiB, 15 minutes by default). A repeat of a completed run with the same
  fingerprint is answered from it (`Idempotent-Replayed: true`, same
  `result_hash`, new `request_id`) without analyzing again; a different
  fingerprint gets `409 RUN_CONFLICT`. After eviction, a repeat is analyzed
  again, which is safe because analysis is deterministic (ADR-004).
- This state is per analyzer process and lost on restart.
- Laravel persists results idempotently. Results for a run that is already
  terminal (`SUCCEEDED`, `FAILED` or `CANCELLED`) are ignored and logged.

## 7. Timeouts, retries and limits

| Setting | Default | Owner / env var |
|---|---|---|
| Analyzer hard time limit per request | 240 s | `ANALYZER_HARD_TIMEOUT_SECONDS` |
| Laravel connect timeout | 5 s | `ANALYZER_CONNECT_TIMEOUT_SECONDS` |
| Laravel request timeout | 300 s | `ANALYZER_TIMEOUT_SECONDS` |
| Job timeout | 330 s | Laravel job `$timeout` |
| Queue `retry_after` | 360 s | Laravel queue config |
| Max attempts per run | 3 | `ANALYZER_MAX_ATTEMPTS` |
| Backoff between attempts | 30 s, then 120 s; `Retry-After` is honoured if larger | Laravel job `backoff()` |
| Max archive size (compressed) | 50 MiB | `ANALYZER_MAX_ARCHIVE_BYTES` |
| Max extracted size | 200 MiB | `ANALYZER_MAX_EXTRACTED_BYTES` |
| Max file count | 20 000 | `ANALYZER_MAX_FILES` |
| Max single archive entry extracted | 25 MiB | `ANALYZER_MAX_ENTRY_BYTES` |
| Max single file analyzed | 1 MiB (larger files are skipped as `too_large`) | `ANALYZER_MAX_FILE_BYTES` |
| Max entry path length | 512 bytes | `ANALYZER_MAX_PATH_LENGTH` |
| Parse time per file | 5000 ms (`PARSE_TIMEOUT` beyond) | `ANALYZER_PARSE_TIMEOUT_MS` |
| Syntax-tree nodes per file / per run | 1 000 000 / 10 000 000 (`LIMIT_EXCEEDED` beyond) | `ANALYZER_MAX_AST_NODES`, `ANALYZER_MAX_TOTAL_AST_NODES` |
| Files parsed per run | 20 000 (`LIMIT_EXCEEDED` beyond) | `ANALYZER_MAX_PARSED_FILES` |
| Source download timeouts (connect / read / total) | 5 s / 30 s / 120 s | `ANALYZER_SOURCE_CONNECT_TIMEOUT_SECONDS`, `..._READ_...`, `..._DOWNLOAD_...` |
| Max pre-signed URL lifetime accepted | 3600 s | `ANALYZER_MAX_URL_LIFETIME_SECONDS` |
| Concurrent analyses per analyzer instance | 2 | `ANALYZER_MAX_CONCURRENCY` |
| Pre-signed URL lifetime | 15 min | `SOURCE_URL_TTL_SECONDS` (Laravel) |

Invariant: `ANALYZER_HARD_TIMEOUT_SECONDS < ANALYZER_TIMEOUT_SECONDS < job
timeout < retry_after`. Laravel validates its own part of the chain at boot.
It also compares against the analyzer's hard limit, which
`GET /internal/v1/health` reports (`limits.hard_timeout_seconds`), and
reports a misconfiguration if the chain is broken.

## 8. Logging

- Both services log `request_id`, `analysis_run_id`, `attempt`, status, error
  code and duration as structured JSON.
- Logs never contain source code, file contents, archive entry names,
  secret values, pre-signed URLs (they are bearer credentials) or HMAC
  secrets or signatures. Unexpected errors log the exception type only.
